# MySQL面试题

## 题目1：MySQL索引的底层数据结构

**问题：** MySQL索引为什么使用B+树而不是B树？

**标准答案：**
1. B+树特点：
   - 所有数据存储在叶子节点
   - 叶子节点通过指针相连，支持范围查询
   - 非叶子节点只存储索引，更矮胖
2. B+树优势：
   - 单次查询数据量更少，IO次数更少
   - 范围查询更高效（叶子链表）
   - 查询性能更稳定（都到叶子节点）
3. B树特点：
   - 数据分布在所有节点
   - 每个节点都存储数据
4. 选择B+树的原因：
   - 磁盘IO更少（更矮胖）
   - 范围查询更高效
   - 查询性能更稳定

**评估要点：**
- 是否理解B+树的结构特点
- 是否知道B+树vs B树的核心差异
- 是否了解磁盘IO的影响

## 题目2：聚簇索引和非聚簇索引

**问题：** 请解释聚簇索引和非聚簇索引的区别。

**标准答案：**
1. 聚簇索引：
   - 数据和索引存储在一起
   - InnoDB的主键索引就是聚簇索引
   - 一张表只能有一个聚簇索引
   - 叶子节点存储完整数据
2. 非聚簇索引（二级索引）：
   - 索引和数据分开存储
   - 叶子节点存储主键值
   - 需要回表查询（先查主键，再查数据）
3. 回表过程：
   - 通过二级索引找到主键
   - 再通过主键在聚簇索引中查找数据
4. 覆盖索引：
   - 查询的列都在索引中
   - 无需回表，效率更高

**评估要点：**
- 是否理解两种索引的区别
- 是否知道回表过程
- 是否理解覆盖索引的优化

## 题目3：事务隔离级别

**问题：** MySQL的四种事务隔离级别分别是什么？各自解决什么问题？

**标准答案：**
1. READ UNCOMMITTED（读未提交）：
   - 问题：脏读、不可重复读、幻读
   - 实际很少使用
2. READ COMMITTED（读已提交）：
   - 解决：脏读
   - 问题：不可重复读、幻读
   - Oracle默认级别
3. REPEATABLE READ（可重复读）：
   - 解决：脏读、不可重复读
   - 问题：幻读（InnoDB通过MVCC+间隙锁解决）
   - MySQL默认级别
4. SERIALIZABLE（串行化）：
   - 解决：所有问题
   - 问题：性能最差
5. InnoDB的MVCC实现：
   - 每行记录有隐藏的事务ID和回滚指针
   - 读操作根据ReadView判断可见性

**评估要点：**
- 是否理解各级别解决的问题
- 是否知道MySQL默认级别
- 是否了解MVCC的实现

## 题目4：如何优化慢查询

**问题：** 如何定位和优化MySQL慢查询？

**标准答案：**
1. 定位慢查询：
   - 开启慢查询日志：slow_query_log=ON
   - 设置阈值：long_query_time=1（秒）
   - 使用mysqldumpslow分析
2. 分析执行计划：
   - EXPLAIN SELECT ...
   - 关注type、key、rows、Extra
3. 优化方法：
   - 添加合适的索引
   - 避免SELECT *
   - 优化JOIN查询（小表驱动大表）
   - 分页查询优化（延迟关联）
   - 避免索引失效（函数、类型转换、OR）
4. 索引失效场景：
   - 对索引列使用函数
   - 隐式类型转换
   - LIKE以%开头
   - OR条件（需建立联合索引）

**评估要点：**
- 是否掌握慢查询定位方法
- 是否理解EXPLAIN结果
- 是否知道常见优化手段

## 题目5：InnoDB和MyISAM的区别

**问题：** InnoDB和MyISAM有什么区别？

**标准答案：**
1. 事务支持：
   - InnoDB支持事务
   - MyISAM不支持事务
2. 锁粒度：
   - InnoDB支持行级锁
   - MyISAM只支持表级锁
3. 外键：
   - InnoDB支持外键
   - MyISAM不支持
4. 索引结构：
   - InnoDB：聚簇索引
   - MyISAM：非聚簇索引，索引和数据分开
5. 崩溃恢复：
   - InnoDB：支持redo log，崩溃恢复
   - MyISAM：不支持，崩溃后数据可能丢失
6. 适用场景：
   - InnoDB：需要事务、高并发写入
   - MyISAM：读多写少、不需要事务

**评估要点：**
- 是否理解两者的核心差异
- 是否知道各自的适用场景
- 是否了解底层实现差异
