# JVM面试题

## 题目1：JVM内存区域划分

**问题：** 请介绍JVM的内存区域划分。

**标准答案：**
1. 线程共享区域：
   - 堆（Heap）：存放对象实例，GC主要区域
   - 方法区（Metaspace）：类信息、常量池、静态变量
2. 线程私有区域：
   - 虚拟机栈：方法调用、局部变量表、操作数栈
   - 本地方法栈：Native方法调用
   - 程序计数器：当前线程执行的字节码行号
3. 堆的分代：
   - 新生代：Eden区 + Survivor区（S0、S1）
   - 老年代：长期存活的对象
4. JDK8变化：移除永久代，使用Metaspace（本地内存）

**评估要点：**
- 是否理解线程共享和私有区域
- 是否知道堆的分代结构
- 是否了解JDK8的变化

## 题目2：垃圾回收算法

**问题：** 请介绍常见的垃圾回收算法。

**标准答案：**
1. 标记-清除：
   - 优点：简单
   - 缺点：内存碎片
2. 复制算法：
   - 优点：无碎片，效率高
   - 缺点：内存利用率低（50%）
   - 应用：新生代（Eden:S0:S1 = 8:1:1）
3. 标记-整理：
   - 优点：无碎片
   - 缺点：效率较低
   - 应用：老年代
4. 分代收集：
   - 新生代：复制算法
   - 老年代：标记-整理
5. 三色标记法：并发标记的实现

**评估要点：**
- 是否理解各算法的优缺点
- 是否知道各算法的应用场景
- 是否了解三色标记法

## 题目3：G1收集器的特点

**问题：** G1收集器有什么特点？与CMS相比有什么优势？

**标准答案：**
1. G1特点：
   - Region划分：堆分为大小相等的Region
   - 并行和并发：充分利用多核
   - 分代收集：仍保留分代概念
   - 可预测停顿：可以设置目标停顿时间
2. G1工作流程：
   - 初始标记（STW）
   - 并发标记
   - 最终标记（STW）
   - 筛选回收（STW）
3. G1 vs CMS：
   - CMS：低停顿，但有内存碎片，可能Concurrent Mode Failure
   - G1：可预测停顿，无碎片，适合大堆
4. 适用场景：堆大小6GB以上

**评估要点：**
- 是否理解Region概念
- 是否知道G1的工作流程
- 是否能对比CMS和G1

## 题目4：类加载机制

**问题：** 请介绍Java的类加载机制。

**标准答案：**
1. 类加载过程：
   - 加载：读取.class文件到方法区
   - 验证：检查文件格式、元数据
   - 准备：为静态变量分配内存并赋初值
   - 解析：符号引用转直接引用
   - 初始化：执行类构造器<clinit>
2. 双亲委派模型：
   - 类加载器优先委托父加载器
   - 避免类的重复加载
   - 保证核心类安全
3. 打破双亲委派：
   - SPI：线程上下文类加载器
   - OSGi：网状类加载
   - Tomcat：每个webapp独立类加载器

**评估要点：**
- 是否理解类加载的各阶段
- 是否理解双亲委派的意义
- 是否知道打破双亲委派的场景

## 题目5：如何排查OOM问题

**问题：** 当应用发生OOM时，如何排查和解决？

**标准答案：**
1. OOM类型：
   - 堆内存溢出：java.lang.OutOfMemoryError: Java heap space
   - 元空间溢出：java.lang.OutOfMemoryError: Metaspace
   - 栈溢出：java.lang.StackOverflowError
2. 排查步骤：
   - 添加JVM参数：-XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=/path
   - 使用MAT或VisualVM分析dump文件
   - 查找大对象和内存泄漏点
3. 常见原因：
   - 内存泄漏：集合类持有对象引用、未关闭资源
   - 内存溢出：确实需要更多内存
4. 解决方法：
   - 内存泄漏：修复代码，释放引用
   - 内存溢出：增大堆内存 -Xmx

**评估要点：**
- 是否知道OOM的类型
- 是否掌握排查工具和步骤
- 是否了解常见原因和解决方法
