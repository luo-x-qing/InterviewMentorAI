# 通用面试评估标准

## 评估维度

### 1. 知识准确性（权重30%）
- **优秀（90-100）**：回答完全正确，概念清晰，无任何错误
- **良好（70-89）**：基本正确，有轻微表述不准确
- **及格（60-69）**：核心概念正确，但有明显遗漏
- **薄弱（0-59）**：概念错误或严重遗漏

### 2. 回答完整性（权重25%）
- **优秀（90-100）**：覆盖所有关键点，逻辑清晰
- **良好（70-89）**：覆盖大部分关键点，有少量遗漏
- **及格（60-69）**：覆盖部分关键点，有明显遗漏
- **薄弱（0-59）**：遗漏大量关键点

### 3. 深度理解（权重25%）
- **优秀（90-100）**：能深入解释原理，有独到见解
- **良好（70-89）**：能解释基本原理，有一定深度
- **及格（60-69）**：仅能复述表面知识
- **薄弱（0-59）**：无法解释原理

### 4. 表达能力（权重20%）
- **优秀（90-100）**：表达清晰，逻辑性强，易于理解
- **良好（70-89）**：表达基本清晰，偶有不连贯
- **及格（60-69）**：表达不够清晰，需要改进
- **薄弱（0-59）**：表达混乱，难以理解

## 综合评分规则

| 总分区间 | 等级 | 描述 |
|---------|------|------|
| 90-100 | PROFICIENT | 优秀，回答准确、全面、有深度 |
| 70-89 | PROFICIENT | 良好，回答基本正确，有小瑕疵 |
| 60-69 | WEAK | 及格，回答不够完整 |
| 0-59 | WEAK | 薄弱，回答有明显错误或遗漏 |

## 常见扣分点

### 技术概念类
- 概念混淆（如HashMap和Hashtable混淆）
- 原理描述不准确
- 遗漏关键特性

### 实践应用类
- 缺少实际案例
- 未说明适用场景
- 未提及注意事项

### 深度理解类
- 仅停留在表面描述
- 未解释底层原理
- 未进行对比分析
