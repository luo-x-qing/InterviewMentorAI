# 系统设计面试题

## 题目1：如何设计一个高并发系统

**问题：** 设计一个高并发系统需要考虑哪些方面？

**标准答案：**
1. 架构层面：
   - 负载均衡：Nginx、F5
   - 分布式架构：微服务拆分
   - 读写分离：主从数据库
   - 缓存策略：Redis、CDN
2. 数据库优化：
   - 分库分表：水平拆分、垂直拆分
   - 索引优化：合理使用索引
   - 连接池：复用数据库连接
3. 应用优化：
   - 异步处理：消息队列
   - 限流降级：Sentinel、Hystrix
   - 线程池：合理配置线程数
4. 监控告警：
   - 性能监控：APM工具
   - 日志分析：ELK Stack
   - 告警机制：及时发现问题

**评估要点：**
- 是否理解高并发的核心挑战
- 是否能设计分层架构
- 是否知道常见的优化手段

## 题目2：如何设计一个缓存系统

**问题：** 设计一个缓存系统需要考虑哪些问题？

**标准答案：**
1. 缓存策略：
   - Cache Aside：先更新数据库，再删除缓存
   - Read/Write Through：缓存代理读写
   - Write Behind：异步写入数据库
2. 缓存问题：
   - 缓存穿透：查询不存在的数据
   - 缓存击穿：热点key过期
   - 缓存雪崩：大量key同时过期
3. 解决方案：
   - 空值缓存：缓存null值
   - 热点key永不过期
   - 过期时间加随机值
   - 布隆过滤器
4. 一致性问题：
   - 最终一致性
   - 延迟双删
   - 订阅binlog

**评估要点：**
- 是否理解缓存策略
- 是否知道缓存问题和解决方案
- 是否能设计缓存一致性方案

## 题目3：如何设计一个消息队列系统

**问题：** 消息队列的核心组件是什么？如何保证消息不丢失？

**标准答案：**
1. 核心组件：
   - Producer：消息生产者
   - Broker：消息存储和转发
   - Consumer：消息消费者
   - Topic/Queue：消息分类
2. 消息不丢失：
   - Producer：同步发送，确认机制
   - Broker：持久化存储，多副本
   - Consumer：手动ACK，消费确认
3. 消息顺序性：
   - 分区有序：同一分区内有序
   - 全局有序：单分区（牺牲性能）
4. 幂等性：
   - 消息ID去重
   - 业务幂等设计
5. 常用MQ：
   - Kafka：高吞吐，日志收集
   - RabbitMQ：功能丰富，企业级
   - RocketMQ：事务消息，分布式事务

**评估要点：**
- 是否理解MQ的核心组件
- 是否知道如何保证消息可靠性
- 是否能根据场景选择MQ

## 题目4：如何设计一个分布式系统

**问题：** 分布式系统的核心问题是什么？如何解决？

**标准答案：**
1. CAP定理：
   - Consistency：一致性
   - Availability：可用性
   - Partition tolerance：分区容错
   - 三者只能满足两个
2. 一致性问题：
   - 强一致性：Raft、Paxos
   - 最终一致性：消息队列、binlog同步
3. 分布式事务：
   - 2PC：两阶段提交
   - TCC：Try-Confirm-Cancel
   - SAGA：长事务
   - 本地消息表
4. 分布式锁：
   - Redis：SETNX
   - Zookeeper：临时顺序节点
   - 数据库：唯一索引
5. 服务治理：
   - 服务注册与发现：Nacos、Eureka
   - 负载均衡：Ribbon、LoadBalancer
   - 熔断降级：Sentinel

**评估要点：**
- 是否理解CAP定理
- 是否知道分布式一致性方案
- 是否能设计分布式事务

## 题目5：如何设计一个微服务架构

**问题：** 微服务架构的核心原则是什么？如何拆分服务？

**标准答案：**
1. 核心原则：
   - 单一职责：每个服务只做一件事
   - 服务自治：独立开发、部署、扩展
   - 轻量通信：HTTP/gRPC
   - 去中心化：独立数据库
2. 服务拆分：
   - 按业务领域拆分：DDD领域驱动设计
   - 按团队组织拆分：康威定律
   - 按变更频率拆分：稳定和频繁变更分离
3. 服务治理：
   - 注册中心：Nacos、Eureka
   - 配置中心：Apollo、Nacos
   - 网关：Spring Cloud Gateway、Zuul
4. 分布式问题：
   - 分布式事务：Seata
   - 链路追踪：SkyWalking、Zipkin
   - 日志聚合：ELK Stack
5. 部署运维：
   - 容器化：Docker
   - 编排：Kubernetes
   - CI/CD：Jenkins、GitLab CI

**评估要点：**
- 是否理解微服务的核心原则
- 是否能合理拆分服务
- 是否知道微服务的治理方案
