MyBatis-Plus：智能仓库管理系统

如果你以前用过 MyBatis，你一定写过大量的 CRUD SQL——增删改查，每个表都要来一遍。MyBatis-Plus 就像给你的仓库装上了一套智能管理系统，常用的出入库操作（CRUD）它都帮你做好了，你只需要写那些特殊的、复杂的查询。

打个比方：以前你需要手动洗碗（手写每条 SQL），现在有了洗碗机（MyBatis-Plus），日常的碗碟（CRUD）直接放进去就好，你只需要处理那些特殊的锅具（复杂查询）。

MyBatis-Plus 核心特性

特性 作用 类比
通用 CRUD 内置 BaseMapper，无需编写基础 SQL 洗碗机自动处理日常碗碟
条件构造器 LambdaQueryWrapper 链式编程，类型安全 智能分拣系统，按条件自动归类
分页插件 内置分页功能，支持多种数据库 自动翻页的库存清单
自动填充 自动填充创建时间、更新时间、租户ID等 自动盖章机，进出库自动盖日期
逻辑删除 支持软删除，数据可恢复 物品不是真扔掉，而是放到"待处理区"
代码生成器 自动生成 Entity、Mapper、Service 等代码 自动生成货架标签和管理文档

数据库表设计

在多租户系统中，数据库表设计就像规划一栋大楼的楼层布局——公共区域放一楼，每层楼有独立的办公空间。

Platform Schema（一楼公共大厅）

这里存放所有租户共享的表——就像商场一楼的物业管理处，管理所有商铺的信息：

-- 租户表 - 住户登记簿
CREATE TABLE t_tenant (
    id          BIGINT AUTO_INCREMENT PRIMARY KEY,
    name        VARCHAR(100) NOT NULL,           -- 公司名称
    schema_name VARCHAR(100) NOT NULL,           -- 对应的楼层编号
    contact_email VARCHAR(100),                  -- 联系邮箱
    status      VARCHAR(20) DEFAULT 'ACTIVE',    -- 状态（在住/退租）
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    deleted     TINYINT DEFAULT 0
);

-- 用户表 - 住户信息
CREATE TABLE t_user (
    id          BIGINT AUTO_INCREMENT PRIMARY KEY,
    tenant_id   BIGINT NOT NULL,                 -- 属于哪个租户
    username    VARCHAR(50) NOT NULL,            -- 登录名
    password    VARCHAR(200) NOT NULL,           -- 加密密码
    real_name   VARCHAR(50),                     -- 真实姓名
    email       VARCHAR(100),
    phone       VARCHAR(20),
    avatar      VARCHAR(200),
    status      VARCHAR(20) DEFAULT 'ACTIVE',
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    deleted     TINYINT DEFAULT 0,
    UNIQUE KEY uk_username_tenant (username, tenant_id)  -- 同一租户内用户名唯一
);

-- 角色表 - 权限级别定义
CREATE TABLE t_role (
    id          BIGINT AUTO_INCREMENT PRIMARY KEY,
    tenant_id   BIGINT NOT NULL,
    role_name   VARCHAR(50) NOT NULL,
    role_code   VARCHAR(50) NOT NULL,
    description VARCHAR(200),
    status      VARCHAR(20) DEFAULT 'ACTIVE',
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    deleted     TINYINT DEFAULT 0
);

-- 用户角色关联表 - 住户权限卡
CREATE TABLE t_user_role (
    id          BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id     BIGINT NOT NULL,
    role_id     BIGINT NOT NULL,
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uk_user_role (user_id, role_id)
);

-- 权限表 - 可用的钥匙类型
CREATE TABLE t_permission (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    permission_name VARCHAR(100) NOT NULL,
    permission_code VARCHAR(100) NOT NULL,
    description     VARCHAR(200),
    created_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    deleted         TINYINT DEFAULT 0
);

-- 角色权限关联表 - 权限卡对应的钥匙
CREATE TABLE t_role_permission (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    role_id         BIGINT NOT NULL,
    permission_id   BIGINT NOT NULL,
    created_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uk_role_permission (role_id, permission_id)
);

Entity 实体映射

Entity 就像数据库表的"身份证"，把表的每个字段映射成 Java 对象的属性。

面试记录实体

@Data                           // 自动生成 getter/setter/toString 等
@TableName("t_interview")       // 指定对应的数据库表名
public class InterviewRecord {

    @TableId(type = IdType.AUTO)  // 主键，自增
    private Long id;

    private Long tenantId;         // 租户ID（楼层数）

    private Long createdBy;        // 创建人
    private Long candidateId;      // 候选人
    private String audioFileId;    // 录音文件
    private String status;         // 状态

    private LocalDateTime updatedAt;
}

Mapper 接口定义

基础 Mapper

继承 BaseMapper 后，常用操作自动就有了：

@Mapper
public interface InterviewRecordMapper extends BaseMapper<InterviewRecord> {

    // BaseMapper 已经提供了这些方法（免费送的）：
    // insert(T entity)                              - 新增
    // deleteById(Serializable id)                   - 按ID删除
    // updateById(T entity)                          - 按ID更新
    // selectById(Serializable id)                   - 按ID查询
    // selectList(Wrapper<T> queryWrapper)           - 条件查询
    // selectPage(Page<T> page, Wrapper<T> queryWrapper) - 分页查询

    // 只需要写那些复杂的、自定义的查询
    @Select("SELECT i.*, u.real_name as candidate_name " +
            "FROM t_interview i " +
            "LEFT JOIN t_user u ON i.candidate_id = u.id " +
            "WHERE i.tenant_id = #{tenantId} " +
            "ORDER BY i.created_at DESC")
    List<Map<String, Object>> selectListWithUser(@Param("tenantId") Long tenantId);
}

条件构造器：智能查询

LambdaQueryWrapper 就像智能搜索引擎——你只需要说"我要找什么"，它自动帮你生成正确的 SQL：

// 查询面试记录（带多种条件）
LambdaQueryWrapper<InterviewRecord> wrapper = new LambdaQueryWrapper<>();
wrapper.eq(InterviewRecord::getTenantId, tenantId)           // 只查当前楼层
       .eq(InterviewRecord::getCreatedBy, userId)            // 只看自己创建的
       .eq(status != null, InterviewRecord::getStatus, status)  // 状态过滤（可选）
       .ge(startTime != null, InterviewRecord::getCreatedAt, startTime)  // 开始时间
       .le(endTime != null, InterviewRecord::getCreatedAt, endTime)      // 结束时间
       .orderByDesc(InterviewRecord::getCreatedAt);          // 按创建时间倒序

// 执行分页查询
Page<InterviewRecord> page = new Page<>(pageNum, pageSize);
IPage<InterviewRecord> result = interviewMapper.selectPage(page, wrapper);

// 统计各状态面试数量（分组统计）
Map<String, Integer> stats = interviewMapper.selectMaps(
        new LambdaQueryWrapper<InterviewRecord>()
                .select(InterviewRecord::getStatus,
                        InterviewRecord::getId.count().as("count"))
                .eq(InterviewRecord::getTenantId, tenantId)
                .groupBy(InterviewRecord::getStatus)
).stream().collect(Collectors.toMap(
        m -> (String) m.get("status"),
        m -> ((Number) m.get("count")).intValue()
));
为什么要用 Lambda 表达式？ 比如 InterviewRecord::getTenantId，如果将来你重命名了 tenantId 字段，编译器会立刻报错。而用字符串 "tenantId" 的话，改了字段名也不会报错，运行时才会发现查询失败。

分页查询

分页就像翻书——你不会一次把整本书看完，而是一页一页地翻。MyBatis-Plus 的分页插件帮你自动实现这个功能。

配置分页插件

@Configuration
public class MybatisPlusConfig {

    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        // 添加分页拦截器，指定数据库类型
        interceptor.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));
        return interceptor;
    }
}

使用分页

@Override
public IPage<InterviewRecord> listInterviews(Long userId, String status,
                                              Integer pageNum, Integer pageSize) {
    Long tenantId = TenantContext.getTenantId();

    // 创建分页对象（第几页，每页几条）
    Page<InterviewRecord> page = new Page<>(pageNum, pageSize);

    LambdaQueryWrapper<InterviewRecord> wrapper = new LambdaQueryWrapper<>()
            .eq(InterviewRecord::getTenantId, tenantId)   // 只查当前楼层
            .eq(userId != null, InterviewRecord::getUserId, userId)
            .eq(status != null, InterviewRecord::getStatus, status)
            .orderByDesc(InterviewRecord::getCreatedAt);

    return interviewMapper.selectPage(page, wrapper);
    // 返回值包含：当前页数据、总条数、总页数等
}

自动填充：自动盖章机

每次插入数据时，创建时间、更新时间、租户ID这些字段不需要手动设置，MyBatis-Plus 会自动帮你填充，就像自动盖章机一样。

@Component
public class AutoFillHandler implements MetaObjectHandler {

    @Override
    public void insertFill(MetaObject metaObject) {
        // 新增时自动填充
        this.strictInsertFill(metaObject, "createdAt", LocalDateTime::now, LocalDateTime.class);
        this.strictInsertFill(metaObject, "updatedAt", LocalDateTime::now, LocalDateTime.class);

        // 自动填充租户ID（从当前上下文获取）
        Long tenantId = TenantContext.getTenantId();
        if (tenantId != null) {
            this.strictInsertFill(metaObject, "tenantId", () -> tenantId, Long.class);
        }
    }

    @Override
    public void updateFill(MetaObject metaObject) {
        // 更新时只填充更新时间
        this.strictUpdateFill(metaObject, "updatedAt", LocalDateTime::now, LocalDateTime.class);
    }
}
自动填充的好处：
  • 不会忘记设置时间字段（以前经常忘记 setCreatedAt）
  • 租户ID从上下文自动获取，不会出错
  • 代码更简洁，不用每个 Service 都写一遍填充逻辑
