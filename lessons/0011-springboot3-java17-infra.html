Spring Boot 3 + Java 17 基础设施

学习目标：
  • 理解为什么选择 Spring Boot 3 + Java 17 作为技术栈
  • 掌握分层架构的设计思想和各层职责
  • 理解构造器注入的优势和使用方式
  • 能够搭建 Spring Boot 项目的基础设施

为什么选择 Spring Boot 3 + Java 17？

想象一下你要盖一栋大楼（开发一个完整的SaaS后端），你当然不想从挖土、烧砖开始。Spring Boot 就像一套预制件系统——它帮你把基础的、重复的脏活累活都干好了，你只需要专注于自己的业务逻辑。

Spring Boot 3 是 Spring 框架的重大升级，基于 Java 17 构建。就像手机系统升级到最新版本一样，你不仅获得了新功能，还得到了更好的性能和安全性。

Java 17 新特性一览

特性 说明 类比
Record 类 简化不可变数据类的定义 像自动生成的快递单，格式固定、内容不可改
Sealed Classes 限制类的继承层次 像VIP俱乐部，只允许指定的成员加入
Pattern Matching 增强的模式匹配能力 像智能快递柜，自动识别包裹大小并分配格子
Text Blocks 多行字符串支持 像便签本，可以自由换行而不用到处加转义符
Switch 表达式 增强的 switch 语法 像交通信号灯，更加智能和安全的路口决策

Spring Boot 3 核心升级

升级项 影响
Jakarta EE 9+ 包名从 javax.* 变为 jakarta.*（需要更新所有 import）
GraalVM 原生编译 可以编译成独立可执行文件，启动速度提升数十倍
HTTP 接口客户端 声明式 HTTP 调用，像写本地方法一样调用远程 API
Observability 内置链路追踪和指标收集，不用额外引入监控框架
Virtual Threads 轻量级线程，一个应用可以轻松处理数十万并发
一句话总结： Spring Boot 3 + Java 17 就像给你的项目装上了一台涡轮增压发动机——更快、更安全、更现代。

分层架构：餐厅运作模式

我们的后端项目采用了经典的分层架构。为了让你更好地理解，我用餐厅来做类比：

层级 餐厅角色 职责
Controller 服务员 接待顾客（接收请求）、记录点单（解析参数）、上菜（返回响应）
Service 厨师 处理核心业务（烹饪）、制定流程（事务管理）、保证质量（数据校验）
Mapper 仓库管理员 管理食材（数据库操作）、进出货记录（CRUD）、盘点库存（查询）
Entity 菜单 定义菜品结构（数据模型）、标注原料（字段映射）
为什么这样分层？ 就像餐厅里服务员不能直接进厨房做饭、厨师不用亲自端盘子一样，分层让每个角色各司其职，系统才能高效运转。如果服务员既要点单又要做菜，那厨房就乱套了。

分层架构详解

接下来，我们深入看看每一层的代码实现。

1. Controller 层（服务员）

服务员的工作很简单：接待顾客、记录需求、把菜端上来。对应到代码里，就是接收HTTP请求、解析参数、返回JSON响应。

@RestController
@RequestMapping("/interview")
public class InterviewController {

    private final InterviewService interviewService;

    // 构造器注入 - 厨师（Service）必须在开餐前就确定
    public InterviewController(InterviewService interviewService) {
        this.interviewService = interviewService;
    }

    @PostMapping
    public Result<InterviewRecord> createInterview(
            @Valid @RequestBody CreateInterviewRequest request,
            Authentication authentication) {
        Long currentUserId = getCurrentUserId(authentication);
        // 记录点单后，直接交给厨师处理
        InterviewRecord record = interviewService.createInterview(request, currentUserId);
        return Result.success(record);
    }
}

2. Service 层（厨师）

厨师是厨房的核心，他决定怎么搭配食材、控制火候、保证质量。对应到代码里，就是业务逻辑、数据校验、事务管理。

@Service
public class InterviewServiceImpl implements InterviewService {

    private final InterviewRecordMapper interviewMapper;
    private final WsPushService wsPushService;

    // 厨师需要知道仓库在哪（Mapper）和对讲机号码（WebSocket）
    public InterviewServiceImpl(InterviewRecordMapper interviewMapper,
                                WsPushService wsPushService) {
        this.interviewMapper = interviewMapper;
        this.wsPushService = wsPushService;
    }

    @Override
    public InterviewRecord createInterview(CreateInterviewRequest request, Long currentUserId) {
        InterviewRecord record = new InterviewRecord();
        record.setTenantId(TenantContext.getTenantId());  // 从门禁卡获取房间号
        record.setUserId(request.getUserId() != null ? request.getUserId() : currentUserId);
        record.setStatus("CREATED");
        record.setCreatedAt(LocalDateTime.now());

        interviewMapper.insert(record);  // 去仓库取食材
        return record;
    }
}

3. Mapper 层（仓库管理员）

仓库管理员负责管理所有食材（数据）的进出，使用 MyBatis-Plus 让操作更高效。

@Mapper
public interface InterviewRecordMapper extends BaseMapper<InterviewRecord> {

    // 自定义复杂查询 - 比如"找出某房间所有过期食材"
    List<Map<String, Object>> selectListWithUser(
            @Param("tenantId") Long tenantId,
            @Param("status") String status);
}

4. Entity 层（菜单/图纸）

定义数据模型，就像餐厅的菜单一样，清楚地标注了每道菜（每张表）有哪些字段。

@Data
@TableName("t_interview")
public class InterviewRecord {

    @TableId(type = IdType.AUTO)
    private Long id;

    private Long tenantId;       // 房间号
    private String title;        // 菜名
    private Long createdBy;      // 点单人
    private Long candidateId;    // 用餐人
    private String audioFileId;  // 配料单
    private String status;       // 制作状态
    private LocalDateTime createdAt;
    private LocalDateTime updatedAt;
}

依赖注入：构造器注入 vs 字段注入

Spring Boot 3 推荐使用构造器注入。这就像招聘厨师时，你希望在入职前就把所有工具准备齐，而不是等厨师入职后再到处找。

推荐：构造器注入

@Service
public class UserServiceImpl implements UserService {

    private final UserMapper userMapper;
    private final PasswordEncoder passwordEncoder;

    // 工具在入职时就确定，之后不会变（final）
    public UserServiceImpl(UserMapper userMapper, PasswordEncoder passwordEncoder) {
        this.userMapper = userMapper;
        this.passwordEncoder = passwordEncoder;
    }
}

不推荐：字段注入

@Service
public class UserServiceImpl implements UserService {

    @Autowired  // 工具随时可能被替换，不稳定
    private UserMapper userMapper;

    @Autowired  // 不推荐 - 依赖不透明
    private PasswordEncoder passwordEncoder;
}
为什么构造器注入更好？
  • 不可变性： 字段可以声明为 final，确保依赖一旦注入就不会变
  • 可测试性： 单元测试时可以直接传入 mock 对象，不用启动 Spring 容器
  • 显式依赖： 构造器参数清楚地展示了这个类需要什么
  • 循环依赖检测： Spring 在启动时就能发现循环依赖，而不是运行时才报错

配置类设计

SecurityConfig（门禁系统配置）

就像小区的门禁系统，有些门任何人都能进（/auth/**），有些门需要刷卡（其他接口）。

@Configuration
@EnableWebSecurity
@EnableMethodSecurity
public class SecurityConfig {

    private final JwtAuthenticationFilter jwtAuthenticationFilter;

    public SecurityConfig(JwtAuthenticationFilter jwtAuthenticationFilter) {
        this.jwtAuthenticationFilter = jwtAuthenticationFilter;
    }

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        http
            .csrf(AbstractHttpConfigurer::disable)  // 关闭 CSRF（API 不需要）
            .sessionManagement(session ->
                session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))  // 无状态
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/auth/**").permitAll()      // 登录页不需要门禁
                .requestMatchers("/session/code/**").permitAll()  // 会议室预约也不需要
                .anyRequest().authenticated()                 // 其他地方都要刷卡
            )
            .addFilterBefore(jwtAuthenticationFilter,
                    UsernamePasswordAuthenticationFilter.class);  // JWT过滤器插在前面

        return http.build();
    }

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();  // 密码加密工具
    }
}

CorsConfig（访客管理配置）

前端和后端通常不在同一个域名，需要配置跨域，就像小区要设置访客进出规则一样。

@Configuration
public class CorsConfig {

    @Bean
    public CorsFilter corsFilter() {
        CorsConfiguration config = new CorsConfiguration();
        config.setAllowedOriginPatterns(List.of("*"));          // 允许所有来源
        config.setAllowedMethods(List.of("GET", "POST", "PUT", "DELETE"));
        config.setAllowedHeaders(List.of("*"));                 // 允许所有头部
        config.setAllowCredentials(true);                       // 允许携带凭证

        UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
        source.registerCorsConfiguration("/**", config);
        return new CorsFilter(source);
    }
}

全局异常处理

不管厨房里出了什么意外（异常），前台服务员都应该给顾客一个友好的提示，而不是让厨师跑出来解释。全局异常处理就是这个作用。

@RestControllerAdvice
public class GlobalExceptionHandler {

    private static final Logger log = LoggerFactory.getLogger(GlobalExceptionHandler.class);

    @ExceptionHandler(BusinessException.class)
    public ResponseEntity<Result<Void>> handleBusinessException(BusinessException e) {
        log.warn("业务异常: {}", e.getMessage());  // 记录日志
        return ResponseEntity.status(HttpStatus.BAD_REQUEST)
                .body(Result.error(e.getCode(), e.getMessage()));  // 返回友好提示
    }

    @ExceptionHandler(Exception.class)
    public ResponseEntity<Result<Void>> handleException(Exception e) {
        log.error("系统异常", e);  // 系统异常需要记录详细信息
        return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR)
                .body(Result.error(500, "系统内部错误"));  // 不要暴露内部细节
    }
}
