RESTful API 设计与 Controller 层

学习目标： 理解 RESTful API 设计原则，掌握统一响应格式，学会设计清晰的 URL 规范，以及在 InterviewMentorAI 中实现规范的 Controller 层。

什么是 RESTful API？餐厅菜单的比喻

想象一下你去餐厅吃饭。餐厅有一份菜单（API 文档），上面列出了所有可选的菜品（资源）和对应的价格（操作）。

  • 资源（Resource）： 菜单上的每道菜就是一个资源，比如"红烧肉"、"清蒸鱼"
  • URL： 每道菜有一个编号，比如 "红烧肉" 是 #1，"清蒸鱼" 是 #2
  • HTTP 方法： 你对这道菜的操作——查看菜单（GET）、点菜（POST）、换菜（PUT）、退菜（DELETE）
  • 状态码： 服务员告诉你"菜做好了"（200）、"没有这道菜"（404）、"厨房着火了"（500）

RESTful API 就是这样一种设计风格：URL 代表资源，HTTP 方法代表操作，状态码代表结果。

核心设计原则

URL 设计规范：好菜单 vs 坏菜单

# 好的 URL 设计（像清晰的菜单）
GET    /interview              # 获取面试列表
POST   /interview              # 创建面试
GET    /interview/{id}         # 获取单个面试
PUT    /interview/{id}         # 更新面试
DELETE /interview/{id}         # 删除面试

# 不好的 URL 设计（像混乱的菜单）
GET    /getInterviewList       # ❌ 使用动词，应该是名词
POST   /createInterview       # ❌ 使用动词
GET    /interview/getById?id=1 # ❌ 查询参数传递ID，应该放在路径中
记住： URL 应该是名词（资源），不是动词（操作）。操作由 HTTP 方法来表示。

HTTP 方法：点菜、换菜、退菜

HTTP 方法 操作 餐厅类比 使用场景
GET 查询 看菜单 获取资源列表或详情
POST 创建 点菜 创建新资源
PUT 更新 换菜 更新整个资源
PATCH 部分更新 加辣/不要香菜 更新资源的部分字段
DELETE 删除 退菜 删除资源

HTTP 状态码：服务员的反馈

状态码 含义 餐厅类比 使用场景
200 OK 菜做好了，请慢用 请求成功
201 Created 您的菜已下单 资源创建成功
204 No Content 已为您退菜 删除成功，无返回内容
400 Bad Request 您点的菜不存在 参数校验失败
401 Unauthorized 请先出示会员卡 未认证
403 Forbidden 抱歉，这道菜不对外出售 无权限
404 Not Found 我们餐厅没有这道菜 资源不存在
500 Internal Server Error 厨房着火了，暂时无法服务 服务器内部错误

统一响应格式

想象一下，如果每家餐厅的账单格式都不一样，有的写中文，有的写英文，有的只有数字，你会很困惑。统一响应格式就是让所有 API 返回的数据格式保持一致。

Result 包装类

@Data
public class Result<T> {
    
    private int code;
    private String message;
    private T data;
    private long timestamp;
    
    public static <T> Result<T> success(T data) {
        Result<T> result = new Result<>();
        result.setCode(200);
        result.setMessage("success");
        result.setData(data);
        result.setTimestamp(System.currentTimeMillis());
        return result;
    }
    
    public static <T> Result<T> error(int code, String message) {
        Result<T> result = new Result<>();
        result.setCode(code);
        result.setMessage(message);
        result.setTimestamp(System.currentTimeMillis());
        return result;
    }
}

Controller 实现示例

InterviewController

@RestController
@RequestMapping("/interview")
public class InterviewController {
    
    private final InterviewService interviewService;
    
    public InterviewController(InterviewService interviewService) {
        this.interviewService = interviewService;
    }
    
    @PostMapping
    public Result<InterviewRecord> createInterview(
            @Valid @RequestBody CreateInterviewRequest request,
            Authentication authentication) {
        Long currentUserId = getCurrentUserId(authentication);
        InterviewRecord record = interviewService.createInterview(request, currentUserId);
        return Result.success(record);
    }
    
    @PostMapping("/{id}/audio")
    public Result<Void> uploadAudio(
            @PathVariable Long id,
            @RequestParam("file") MultipartFile file,
            Authentication authentication) {
        Long currentUserId = getCurrentUserId(authentication);
        interviewService.uploadAudioAndAnalyze(id, file, currentUserId);
        return Result.success(null);
    }
    
    @GetMapping
    public Result<IPage<InterviewRecord>> listInterviews(
            @RequestParam(required = false) Long userId,
            @RequestParam(required = false) String status,
            @RequestParam(defaultValue = "1") Integer pageNum,
            @RequestParam(defaultValue = "20") Integer pageSize,
            Authentication authentication) {
        Long currentUserId = getCurrentUserId(authentication);
        IPage<InterviewRecord> page = interviewService.listInterviews(
                userId, status, pageNum, pageSize);
        return Result.success(page);
    }
    
    @GetMapping("/stats")
    public Result<Map<String, Integer>> getInterviewStats() {
        Map<String, Integer> stats = interviewService.getInterviewStats();
        return Result.success(stats);
    }
    
    private Long getCurrentUserId(Authentication authentication) {
        UserDetails userDetails = (UserDetails) authentication.getPrincipal();
        return 1L; // 简化示例
    }
}

全局异常处理

全局异常处理就像餐厅的"万能服务员"——不管发生什么问题，都能给顾客一个合理的解释。

@RestControllerAdvice
public class GlobalExceptionHandler {
    
    @ExceptionHandler(BusinessException.class)
    public ResponseEntity<Result<Void>> handleBusinessException(BusinessException e) {
        log.warn("业务异常: {}", e.getMessage());
        return ResponseEntity.status(HttpStatus.BAD_REQUEST)
                .body(Result.error(e.getCode(), e.getMessage()));
    }
    
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<Result<Void>> handleValidationException(
            MethodArgumentNotValidException e) {
        String message = e.getBindingResult().getFieldErrors().stream()
                .map(error -> error.getField() + ": " + error.getDefaultMessage())
                .collect(Collectors.joining("; "));
        return ResponseEntity.status(HttpStatus.BAD_REQUEST)
                .body(Result.error(400, message));
    }
    
    @ExceptionHandler(AccessDeniedException.class)
    public ResponseEntity<Result<Void>> handleAccessDeniedException(AccessDeniedException e) {
        return ResponseEntity.status(HttpStatus.FORBIDDEN)
                .body(Result.error(403, "无权限访问"));
    }
    
    @ExceptionHandler(Exception.class)
    public ResponseEntity<Result<Void>> handleException(Exception e) {
        log.error("系统异常", e);
        return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR)
                .body(Result.error(500, "系统内部错误"));
    }
}
最佳实践： 使用 @RestControllerAdvice 可以统一处理所有 Controller 的异常，避免在每个 Controller 中重复编写异常处理代码。
