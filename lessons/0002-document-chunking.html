文档分块策略

学习目标： 掌握文档分块的原理、常见策略和最佳实践，理解分块对RAG系统效果的影响。

为什么需要文档分块？

在RAG系统中，文档分块（Chunking）是将长文档拆分为短文本片段的过程。这是RAG流水线中至关重要的一步，原因如下：

  • 检索精度： 检索是按块进行的，块太大可能导致找到一整章但真正有用的只有两行
  • 上下文窗口限制： 即使模型上下文窗口很大，也无法塞下整个知识库
  • 语义完整性： 合理的分块能保持每个块的语义完整性
  • 检索效率： 较小的块可以更快地进行相似度计算
关键点： 分块策略是RAG系统效果差异的主要来源之一。选择合适的分块策略对检索质量至关重要。

常见分块策略

1. 固定长度分块

最简单的分块方法，按照固定的字符数或词数进行分割。

# 示例：固定长度分块
chunk_size = 500  # 每个块500个字符
chunk_overlap = 50  # 块之间重叠50个字符

优点： 实现简单，计算快速

缺点： 可能破坏语义完整性，导致重要信息被切断

2. 基于文档结构的分块

根据文档的自然结构进行分割，如章节、段落、列表等。

# 示例：按章节分块
# 文档结构：
# 第一章：介绍
#   1.1 背景
#   1.2 目标
# 第二章：方法
#   2.1 实验设计
#   2.2 数据收集

# 分块结果：
# 块1：第一章介绍
# 块2：1.1 背景
# 块3：1.2 目标
# 块4：第二章方法
# ...

优点： 保持语义完整性，块内信息自包含

缺点： 需要了解文档结构，实现复杂

3. 语义分块

基于语义相似度进行分割，确保每个块讨论一个连贯的主题。

# 示例：语义分块
# 原理：当相邻句子的语义相似度低于阈值时，进行分割

# 文档内容：
# "Python是一种解释型语言。它支持多种编程范式。
# Java是一种编译型语言。它广泛应用于企业级开发。"

# 语义分块结果：
# 块1："Python是一种解释型语言。它支持多种编程范式。"
# 块2："Java是一种编译型语言。它广泛应用于企业级开发。"

优点： 语义完整性最好，检索效果最佳

缺点： 计算成本高，需要嵌入模型

4. 递归字符分割

LangChain推荐的方法，尝试按多种分隔符进行分割，保持块的连贯性。

# 示例：递归字符分割
from langchain.text_splitter import RecursiveCharacterTextSplitter

text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000,
    chunk_overlap=200,
    length_function=len,
    add_start_index=True,
)

# 分割优先级：
# 1. 段落分隔符 "\n\n"
# 2. 句子分隔符 "\n"
# 3. 词分隔符 " "
# 4. 字符分隔符 ""

优点： 平衡了语义完整性和实现复杂度

缺点： 需要调优参数

分块参数调优

块大小（Chunk Size）

  • 太小： 可能丢失上下文信息，检索结果碎片化
  • 太大： 可能包含无关信息，降低检索精度
  • 推荐范围： 200-1000个字符，根据应用场景调整

重叠大小（Chunk Overlap）

  • 作用： 确保重要信息不会被切断
  • 推荐范围： 块大小的10%-20%
  • 权衡： 重叠越大，存储和计算成本越高

InterviewMentorAI项目中的分块策略

针对InterviewMentorAI项目，我们需要考虑以下特殊需求：

项目特定需求：
  • 面试对话是连续的，需要保持对话的连贯性
  • 问题和回答应该作为整体进行检索
  • 需要区分面试官和应聘者的对话
  • 评估报告需要引用具体的对话片段

推荐策略

对于InterviewMentorAI项目，建议采用以下分块策略：

  1. 按对话轮次分块： 每个问题-回答对作为一个块
  2. 保留上下文： 在每个块中包含前一轮对话的摘要
  3. 元数据标注： 为每个块添加说话人、时间戳等元数据
  4. 重叠策略： 相邻块之间保留10%的重叠，确保连贯性
