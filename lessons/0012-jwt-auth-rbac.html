JWT 认证与 RBAC 权限体系

学习目标：
  • 理解认证（Authentication）和授权（Authorization）的区别
  • 掌握 JWT（JSON Web Token）的结构和工作原理
  • 理解双 Token 机制的安全优势
  • 掌握 RBAC 权限模型和三层角色设计
  • 学会在 Spring Security 中实现 JWT 认证和权限控制

认证 vs 授权：身份证 vs 门禁卡

先来搞清楚两个经常被混淆的概念。想象你搬进了一个高档小区：

  • 认证（Authentication） = 出示身份证，证明"我是小区业主张三"
  • 授权（Authorization） = 刷门禁卡，系统检查"张三的卡能不能进健身房？"

没有身份证（认证），保安根本不让你进门。有了身份证但没有健身房权限（授权），你只能去花园散步。

记忆技巧： 认证是"确认你是谁"，授权是"决定你能干嘛"。先认证，后授权。

JWT：你的"电子身份证"

JWT（JSON Web Token）就像一张电子身份证，它把用户信息编码成一个加密字符串，服务器通过检查这张"电子身份证"来确认你的身份。

JWT 长什么样？

一个 JWT Token 由三部分组成，用点号分隔：

Header.Payload.Signature

eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiJ1c2VyMSIsImV4cCI6MTcwMDAwMDAwMH0.signature

把它想象成一张演唱会门票：

JWT 部分 演唱会门票类比 实际内容
Header（头部） 票面印刷方式 算法（HS256）和令牌类型（JWT）
Payload（载荷） 门票上的信息 用户ID、角色、过期时间等
Signature（签名） 防伪标识/二维码 用密钥加密的签名，防止伪造

Payload 里装了什么？

Payload 是 JWT 的"信息载体"，就像门票上印着你的姓名、座位号、演出时间等：

{
  "sub": "user1",              // 用户标识（相当于门票上的姓名）
  "username": "张三",          // 用户名
  "tenantId": 1,               // 租户ID（你在哪个小区）
  "roles": ["TENANT_MEMBER"],  // 角色（你的门禁权限级别）
  "iat": 1700000000,           // 签发时间（门票印制日期）
  "exp": 1700007200            // 过期时间（门票有效期）
}

Signature 防伪机制

签名确保门票没有被PS过。服务器用只有自己知道的密钥来验证：

HMACSHA256(
  base64UrlEncode(header) + "." + base64UrlEncode(payload),  // 票面信息
  secret                                                      // 服务器的密钥
)
安全提醒： JWT 的 Payload 部分只是 Base64 编码，不是加密！任何人都能读取其中的内容。所以不要在 Payload 中存放密码等敏感信息。

双 Token 机制：安全的"双保险"

在 InterviewMentorAI 中，我们采用双 Token 机制。这就像你的手机同时有"指纹锁"和"密码锁"——指纹锁日常使用（短期），密码锁在指纹锁失效时使用（长期）。

Token 类型 有效期 用途 类比
accessToken 2 小时 API 鉴权 临时工牌，用完就扔
refreshToken 7 天 刷新 accessToken 补办卡，可以换新工牌

完整认证流程

想象你去公司上班的一天：

1. 登录（到公司前台）
   POST /auth/login { username, password }
   ↓
2. 服务器验证密码，生成双 Token
   { accessToken(2小时), refreshToken(7天), userInfo }
   ↓
3. 客户端存储 Token，后续请求携带 accessToken
   Authorization: Bearer eyJhbGci...
   ↓
4. 服务器验证 accessToken，解析用户信息
   JwtAuthenticationFilter → 解析 JWT → SecurityContext
   ↓
5. accessToken 过期（工牌到期），使用 refreshToken 刷新
   POST /auth/refresh?refreshToken=xxx
   ↓
6. refreshToken 过期（补办卡也到期），需要重新登录
   POST /auth/login  ← 重新去前台

JWT Token 生成代码

下面是生成和验证 Token 的核心代码：

@Component
public class JwtTokenProvider {

    private final SecretKey key;
    private final long accessTokenExpiration;
    private final long refreshTokenExpiration;

    public JwtTokenProvider(
            @Value("${jwt.secret}") String secret,
            @Value("${jwt.access-token-expiration}") long accessTokenExpiration,
            @Value("${jwt.refresh-token-expiration}") long refreshTokenExpiration) {
        this.key = Keys.hmacShaKeyFor(Decoders.BASE64.decode(
                java.util.Base64.getEncoder().encodeToString(secret.getBytes())));
        this.accessTokenExpiration = accessTokenExpiration;
        this.refreshTokenExpiration = refreshTokenExpiration;
    }

    public String generateAccessToken(Authentication authentication) {
        UserDetails userDetails = (UserDetails) authentication.getPrincipal();
        Date now = new Date();
        Date expiryDate = new Date(now.getTime() + accessTokenExpiration);

        return Jwts.builder()
                .subject(userDetails.getUsername())
                .issuedAt(now)
                .expiration(expiryDate)
                .signWith(key)
                .compact();
    }

    public boolean validateToken(String token) {
        try {
            Jwts.parser().verifyWith(key).build().parseSignedClaims(token);
            return true;
        } catch (JwtException | IllegalArgumentException e) {
            return false;
        }
    }
}

RBAC 权限模型：酒店钥匙卡系统

RBAC（Role-Based Access Control，基于角色的访问控制）就像酒店的钥匙卡系统。你不是直接拿到"打开所有房间"的万能钥匙，而是根据你的身份（房客/经理/总经理）拿到不同权限的钥匙卡。

用户 (User)  ←→  角色 (Role)  ←→  权限 (Permission)
  ↓                  ↓                  ↓
张三            TENANT_MEMBER      interview:create
李四            TENANT_ADMIN       report:edit
王五            PLATFORM_ADMIN     tenant:manage

三层角色设计

InterviewMentorAI 设计了三层角色，就像酒店的三个管理层级：

角色 酒店类比 权限范围
PLATFORM_ADMIN 酒店总经理 管理所有租户、订阅计划、系统配置
TENANT_ADMIN 楼层经理 管理本租户成员、知识库、查看所有面试报告
TENANT_MEMBER 普通房客 创建面试、上传音频、查看自己报告

Spring Security Filter Chain

每个 HTTP 请求进入系统后，会经过一系列"关卡"检查。就像你进入酒店时：先过门卫（CorsFilter），再验工牌（JwtAuthenticationFilter），然后查楼层（TenantFilter），最后到房间时再查房间权限。

HTTP Request
  ↓
CorsFilter                 → 处理跨域（门卫检查外来人员）
  ↓
JwtAuthenticationFilter    → 解析 JWT（验工牌真伪）
  ↓                         → 加载用户角色和权限（查你的权限级别）
  ↓                         → 注入 SecurityContext（记录到访客簿）
TenantFilter               → 解析租户 ID（确定你在哪个楼层）
  ↓                         → 设置 TenantContext
FilterSecurityInterceptor  → RBAC 权限校验（查你有没有进这个房间的权限）
  ↓                         → @PreAuthorize 注解检查
Controller                 → 业务处理（进入房间做事）

JwtAuthenticationFilter 代码

这是"验工牌"的门卫，每个请求都要经过他：

@Component
public class JwtAuthenticationFilter extends OncePerRequestFilter {

    private final JwtTokenProvider tokenProvider;
    private final CustomUserDetailsService userDetailsService;

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                    HttpServletResponse response,
                                    FilterChain filterChain) throws ServletException, IOException {
        String token = extractToken(request);  // 从请求中提取工牌

        if (StringUtils.hasText(token) && tokenProvider.validateToken(token)) {
            String username = tokenProvider.getUsernameFromToken(token);
            // 去住户信息库查这个人的权限
            UserDetails userDetails = userDetailsService.loadUserByUsername(username);

            // 把验证结果写入访客簿
            UsernamePasswordAuthenticationToken authentication =
                    new UsernamePasswordAuthenticationToken(
                            userDetails, null, userDetails.getAuthorities());
            authentication.setDetails(
                    new WebAuthenticationDetailsSource().buildDetails(request));

            SecurityContextHolder.getContext().setAuthentication(authentication);
        }

        filterChain.doFilter(request, response);  // 放行，让后面的关卡继续检查
    }

    private String extractToken(HttpServletRequest request) {
        String bearerToken = request.getHeader("Authorization");
        if (StringUtils.hasText(bearerToken) && bearerToken.startsWith("Bearer ")) {
            return bearerToken.substring(7);
        }
        return null;
    }
}

权限注解使用

使用 @PreAuthorize 注解可以在方法级别进行权限控制，就像每个房间门口贴了"仅限XX进入"的牌子：

@RestController
@RequestMapping("/tenant")
public class TenantController {

    @PostMapping("/create")
    @PreAuthorize("hasRole('PLATFORM_ADMIN')")  // 仅总经理可操作
    public Result<Map<String, Object>> createTenant(@RequestBody Map<String, String> request) {
        // ...
    }

    @GetMapping("/members")
    @PreAuthorize("hasAnyRole('PLATFORM_ADMIN', 'TENANT_ADMIN')")  // 总经理或楼层经理
    public Result<IPage<User>> listMembers(...) {
        // ...
    }
}

用户详情加载

当系统需要知道"张三有哪些权限"时，会调用这个服务去数据库查询：

@Service
public class CustomUserDetailsService implements UserDetailsService {

    private final UserMapper userMapper;

    @Override
    public UserDetails loadUserByUsername(String username) throws UsernameNotFoundException {
        // 去住户信息库找这个人
        User user = userMapper.selectOne(
                new LambdaQueryWrapper<User>().eq(User::getUsername, username));

        if (user == null) {
            throw new UsernameNotFoundException("用户不存在: " + username);
        }

        // 查询这个人的所有角色（楼层权限）
        List<SimpleGrantedAuthority> authorities = userMapper.selectRoleCodesByUserId(user.getId())
                .stream()
                .map(SimpleGrantedAuthority::new)
                .toList();

        return new org.springframework.security.core.userdetails.User(
                user.getUsername(),
                user.getPassword(),
                authorities
        );
    }
}
