异步调用与 WebSocket 推送

学习目标： 理解异步处理与同步处理的区别，掌握 Spring @Async 线程池配置，学会使用 STOMP WebSocket 实现实时通信，以及使用 RestClient 调用 Python AI 后端。

为什么需要异步处理？

想象一下你去餐厅点餐。有两种方式：

  • 同步方式： 你站在柜台前，盯着厨师做菜，直到菜端上来才能离开。在这期间你什么都干不了，厨师也被你盯着压力山大。
  • 异步方式： 你点完餐后，服务员给你一个取餐器（buzzer）。你可以先去座位上玩手机、聊天，等取餐器响了再来取餐。厨师可以专心做菜，你也可以做自己的事。

在 InterviewMentorAI 中，Python AI 后端分析音频需要 30 秒到 2 分钟。如果用同步方式，用户的界面会"卡死"在那里等待。用异步方式，用户可以继续操作，等分析完成再收到通知。

同步 vs 异步对比

方式 用户体验 服务器资源 适用场景 类比
同步 差（需等待） 占用线程 快速操作（< 1秒） 站在柜台等餐
异步 好（立即返回） 释放线程 耗时操作（> 1秒） 拿取餐器等通知

异步处理流程

用户上传音频
  ↓
Java 后端接收请求
  ↓
立即返回 "分析中" 状态  ← 用户可以继续操作
  ↓
异步调用 Python AI 后端（@Async）
  ↓
通过 STOMP 推送进度给 Flutter
  ↓
Python 返回结果
  ↓
更新数据库，推送最终结果给 Flutter  ← 用户收到通知
关键点： 异步处理的核心是"立即返回，后台处理"。用户不需要等待耗时操作完成，服务器也不会因为长时间等待而阻塞。

Spring @Async 异步执行

线程池：餐厅的厨房

想象一下餐厅的厨房。厨房里有有限数量的厨师（线程），他们同时能处理的订单数量是有限的。如果来了一百个订单，厨师们会先做前几个，剩下的排队等待。

Spring 的线程池就是这样工作的：

启用异步支持

@Configuration
@EnableAsync
public class AsyncConfig {
    
    @Bean("aiAnalysisExecutor")
    public Executor aiAnalysisExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(4);        // 核心厨师数（常驻）
        executor.setMaxPoolSize(8);         // 最大厨师数（高峰期）
        executor.setQueueCapacity(50);      // 等候区座位数
        executor.setThreadNamePrefix("ai-analysis-");
        executor.initialize();
        return executor;
    }
}

这里有几个关键参数：

  • corePoolSize (4)： 常驻厨师数量，即使没活干也保持
  • maxPoolSize (8)： 高峰期最多可以有 8 个厨师同时工作
  • queueCapacity (50)： 等候区最多坐 50 个订单，超过就拒绝

异步方法定义

@Service
public class InterviewServiceImpl implements InterviewService {
    
    @Async("aiAnalysisExecutor")  // 指定使用哪个线程池
    public void analyzeAudioAsync(Long interviewId, Long tenantId, String audioFileId) {
        try {
            // 1. 推送"分析中"状态
            wsPushService.pushAnalysisStatus(tenantId, interviewId, "analyzing");
            
            // 2. 调用 Python AI 后端
            String result = callPythonAiBackend(audioFileId);
            
            // 3. 解析结果，保存到数据库
            Evaluation evaluation = parseAndSaveEvaluation(result, interviewId);
            
            // 4. 推送分析完成
            wsPushService.pushAnalysisComplete(tenantId, interviewId, evaluation);
            
        } catch (Exception e) {
            // 5. 推送分析失败
            wsPushService.pushAnalysisError(tenantId, interviewId, e.getMessage());
        }
    }
    
    private String callPythonAiBackend(String audioFileId) {
        RestClient restClient = RestClient.create();
        String url = "http://localhost:8000/api/analysis";
        
        Map<String, String> request = Map.of("audio_file_id", audioFileId);
        
        String response = restClient.post()
                .uri(url)
                .contentType(MediaType.APPLICATION_JSON)
                .body(request)
                .retrieve()
                .body(String.class);
        
        return response;
    }
}
注意： @Async 方法的返回值如果是 void，调用者不会等待方法执行完成。这就是"发射后不管"的模式——调用者只负责触发，不负责等待结果。

WebSocket STOMP 协议

什么是 STOMP？对讲机系统

想象一下工地上的对讲机系统：

  • 每个人都有一个对讲机（WebSocket 连接）
  • 大家调到同一个频道（Topic）就能收到广播消息
  • 你可以选择只听某个频道（订阅特定 Topic）
  • 消息是结构化的（有格式的），不是乱七八糟的噪音

STOMP（Simple Text Oriented Messaging Protocol）就是这样一个结构化的消息协议，它基于 WebSocket，但提供了更规范的消息格式。

Socket.IO vs STOMP 对比

特性 Socket.IO（旧方案） STOMP（新方案）
协议 自有协议 标准 STOMP 协议
消息格式 JSON 字符串 结构化帧
Spring 集成 需第三方库 原生支持
负载均衡 复杂 简单（使用 /topic）

WebSocket 配置

@Configuration
@EnableWebSocketMessageBroker
public class WebSocketConfig implements WebSocketMessageBrokerConfigurer {
    
    @Override
    public void configureMessageBroker(MessageBrokerRegistry registry) {
        // 使用内置 broker，"/topic" 前缀用于广播
        registry.enableSimpleBroker("/topic");
        // 客户端发送消息的前缀
        registry.setApplicationDestinationPrefixes("/app");
    }
    
    @Override
    public void registerStompEndpoints(StompEndpointRegistry registry) {
        // WebSocket 连接端点
        registry.addEndpoint("/ws")
                .setAllowedOriginPatterns("*")
                .withSockJS();  // 支持 SockJS 降级
    }
}

推送服务实现

@Service
public class WsPushService {
    
    private final SimpMessagingTemplate messagingTemplate;
    
    public WsPushService(SimpMessagingTemplate messagingTemplate) {
        this.messagingTemplate = messagingTemplate;
    }
    
    // 推送面试创建成功
    public void pushInterviewCreated(Long tenantId, Long interviewId, Long userId) {
        String destination = "/topic/interview/created/" + userId;
        Map<String, Object> payload = Map.of(
            "interviewId", interviewId,
            "status", "CREATED",
            "timestamp", LocalDateTime.now()
        );
        messagingTemplate.convertAndSend(destination, payload);
    }
    
    // 推送音频上传成功
    public void pushAudioUploaded(Long tenantId, Long interviewId, Long userId) {
        String destination = "/topic/interview/audio/" + userId;
        Map<String, Object> payload = Map.of(
            "interviewId", interviewId,
            "status", "UPLOADED",
            "timestamp", LocalDateTime.now()
        );
        messagingTemplate.convertAndSend(destination, payload);
    }
    
    // 推送分析状态
    public void pushAnalysisStatus(Long tenantId, Long interviewId, String status) {
        String destination = "/topic/interview/analysis/" + interviewId;
        Map<String, Object> payload = Map.of(
            "interviewId", interviewId,
            "status", status,  // analyzing / completed / error
            "timestamp", LocalDateTime.now()
        );
        messagingTemplate.convertAndSend(destination, payload);
    }
    
    // 推送分析完成
    public void pushAnalysisComplete(Long tenantId, Long interviewId, Evaluation evaluation) {
        String destination = "/topic/interview/analysis/" + interviewId;
        Map<String, Object> payload = Map.of(
            "interviewId", interviewId,
            "status", "completed",
            "evaluation", evaluation,
            "timestamp", LocalDateTime.now()
        );
        messagingTemplate.convertAndSend(destination, payload);
    }
    
    // 推送分析失败
    public void pushAnalysisError(Long tenantId, Long interviewId, String error) {
        String destination = "/topic/interview/analysis/" + interviewId;
        Map<String, Object> payload = Map.of(
            "interviewId", interviewId,
            "status", "error",
            "error", error,
            "timestamp", LocalDateTime.now()
        );
        messagingTemplate.convertAndSend(destination, payload);
    }
}

Flutter 端接收

// Flutter WebSocket 连接和订阅
class WebSocketService {
  late StompClient stompClient;
  
  void connect(String userId) {
    stompClient = StompClient(
      config: StompConfig(
        url: 'http://localhost:8080/ws',
        onConnect: (frame) {
          // 订阅面试创建事件
          stompClient.subscribe(
            destination: '/topic/interview/created/$userId',
            callback: (frame) {
              final data = json.decode(frame.body!);
              handleInterviewCreated(data);
            },
          );
          
          // 订阅分析进度事件
          stompClient.subscribe(
            destination: '/topic/interview/analysis/$interviewId',
            callback: (frame) {
              final data = json.decode(frame.body!);
              handleAnalysisProgress(data);
            },
          );
        },
      ),
    );
    stompClient.activate();
  }
}

RESTClient 调用 Python

Spring 6 提供了新的 RestClient，替代了旧的 RestTemplate。它更简洁、更现代：

@Service
public class PythonAiClient {
    
    private final RestClient restClient;
    
    public PythonAiClient(@Value("${python.ai.backend.url}") String baseUrl) {
        this.restClient = RestClient.create(baseUrl);
    }
    
    public Map<String, Object> analyzeAudio(String audioFileId, String audioFormat) {
        Map<String, String> request = Map.of(
            "audio_file_id", audioFileId,
            "audio_format", audioFormat
        );
        
        return restClient.post()
                .uri("/api/analysis")
                .contentType(MediaType.APPLICATION_JSON)
                .body(request)
                .retrieve()
                .body(Map.class);
    }
}
RestClient vs RestTemplate： RestClient 是 Spring 6 推荐的 HTTP 客户端，API 更简洁，支持链式调用，且与 Spring 生态集成更好。
