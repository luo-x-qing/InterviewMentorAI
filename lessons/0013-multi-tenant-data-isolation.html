多租户数据隔离设计

学习目标：
  • 理解多租户数据隔离的三种策略及其适用场景
  • 掌握 TenantContext（租户上下文）的设计思想
  • 理解 TenantFilter（租户过滤器）的工作原理
  • 掌握 Schema 初始化流程
  • 学会在查询层面实现租户数据隔离

回顾：三种隔离策略

在多租户架构中，数据隔离是最核心的问题。就像一个商场里有很多商铺，怎么保证A商铺看不到B商铺的账本？有三种主流方案：

策略 商场类比 隔离级别 成本
独立数据库 每个商铺有自己的仓库大楼 最高 最高
独立 Schema 同一栋楼，但每个商铺有自己的楼层 高 中
共享表 + 租户ID 同一栋楼，同一层，靠编号区分 中 低
InterviewMentorAI 的选择： 我们采用混合方案——共享数据库 + 独立 Schema + tenant_id 字段。就像一栋大楼里，一楼是公共区域（平台库），每个租户在自己的楼层有独立的办公空间（租户库），同时每个人的桌子上都贴着自己的工号（tenant_id）。

TenantContext：你的"房间号"

TenantContext 就像你进入大楼后，门卫给你的一个"房间号"。在整个工作过程中（一个请求的生命周期），你随时可以查看自己的房间号，确保你在正确的楼层工作。

技术上，我们使用 ThreadLocal 来存储当前请求的租户 ID。ThreadLocal 就像一个"个人便签本"，只有当前线程（当前工作人员）能看到，别人看不到。

public class TenantContext {

    // ThreadLocal - 每个线程自己的便签本
    private static final ThreadLocal<Long> CURRENT_TENANT_ID = new ThreadLocal<>();

    // 写入房间号（门卫分配房间）
    public static void setTenantId(Long tenantId) {
        CURRENT_TENANT_ID.set(tenantId);
    }

    // 读取房间号（随时查看自己在哪个房间）
    public static Long getTenantId() {
        return CURRENT_TENANT_ID.get();
    }

    // 清除房间号（下班时擦掉便签，防止泄漏给下一个人）
    public static void clear() {
        CURRENT_TENANT_ID.remove();
    }
}
关键点： 必须在请求结束时调用 clear() 清除 ThreadLocal，否则可能造成内存泄漏或数据串租户（A租户看到B租户的数据）。

TenantFilter：楼层门禁

TenantFilter 就像每个楼层的门禁系统——每个请求进来时，它会检查你的工牌（JWT Token），确定你在哪个楼层，然后把楼层号记录下来。

@Component
public class TenantFilter implements Filter {

    private final TenantService tenantService;

    @Override
    public void doFilterInternal(HttpServletRequest request,
                                 HttpServletResponse response,
                                 FilterChain filterChain) throws ServletException, IOException {
        try {
            // 从门禁卡（JWT Token）中提取楼层号（tenantId）
            Authentication authentication = SecurityContextHolder.getContext().getAuthentication();
            if (authentication != null && authentication.getPrincipal() instanceof UserDetails) {
                Long tenantId = extractTenantId(authentication);
                TenantContext.setTenantId(tenantId);  // 记录到个人便签本
            }

            filterChain.doFilter(request, response);
        } finally {
            TenantContext.clear();  // 下班时擦掉便签，防止内存泄漏
        }
    }
}

Schema 初始化流程

当新租户注册时，就像新房客搬进大楼，需要为他准备好独立的办公空间：

1. 新租户注册（新房客来前台登记）
   ↓
2. 在 platform.ttenant 插入租户记录（登记到住户簿）
   ↓
3. 创建新 Schema: tenant_{id}（分配独立楼层）
   ↓
4. 执行 schema-tenant.sql 初始化表结构（摆放办公家具）
   ↓
5. 租户可以开始使用系统（新房客开始办公）

TenantService 实现

这是"房管部门"的核心代码，负责为新租户创建独立空间：

@Service
public class TenantServiceImpl implements TenantService {

    private final JdbcTemplate jdbcTemplate;

    @Override
    public Map<String, Object> createTenant(String tenantName, String contactEmail) {
        // 1. 创建独立楼层（Schema）
        String schemaName = "tenant_" + System.currentTimeMillis();
        jdbcTemplate.execute("CREATE SCHEMA " + schemaName);

        // 2. 摆放家具（执行初始化SQL）
        Resource resource = new ClassPathResource("schema-tenant.sql");
        String sql = new String(resource.getInputStream().readAllBytes());
        sql = sql.replace("${schema_name}", schemaName);
        jdbcTemplate.execute(sql);

        // 3. 登记到住户簿（插入租户记录）
        Tenant tenant = new Tenant();
        tenant.setName(tenantName);
        tenant.setSchemaName(schemaName);
        tenant.setContactEmail(contactEmail);
        tenant.setStatus(TenantStatus.ACTIVE);
        tenantMapper.insert(tenant);

        return Map.of("tenantId", tenant.getId(), "schemaName", schemaName);
    }
}

查询隔离机制

数据隔离的最后一步是确保每次查询都只返回当前租户的数据。这就像餐厅服务员只会把你点的菜端给你，不会端给隔壁桌。

MyBatis-Plus 自动填充

插入数据时，自动加上租户ID，就像给每件物品贴上"属于XX房间"的标签：

@Component
public class MybatisPlusConfig implements MetaObjectHandler {

    @Override
    public void insertFill(MetaObject metaObject) {
        Long tenantId = TenantContext.getTenantId();
        if (tenantId != null) {
            // 自动贴上"房间号"标签
            strictInsertFill(metaObject, "tenantId", Long.class, tenantId);
        }
    }
}

Service 层手动过滤

查询数据时，必须带上租户条件，就像查库存时必须先确认是哪个仓库：

@Override
public IPage<InterviewRecord> listInterviews(Long userId, String status, Page<InterviewRecord> page) {
    Long tenantId = TenantContext.getTenantId();  // 获取当前楼层号

    LambdaQueryWrapper<InterviewRecord> wrapper = new LambdaQueryWrapper<>()
            .eq(InterviewRecord::getTenantId, tenantId)  // 强制只查当前楼层
            .eq(userId != null, InterviewRecord::getUserId, userId)
            .eq(status != null, InterviewRecord::getStatus, status)
            .orderByDesc(InterviewRecord::getCreatedAt);

    return interviewMapper.selectPage(page, wrapper);
}
安全原则： 永远不要信任前端传入的 tenantId。必须从已认证的用户信息中获取，防止租户数据泄露。就像你不能让顾客自己说"我是XX房间的"，必须刷门禁卡验证。
