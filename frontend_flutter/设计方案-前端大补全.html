一、设计思路
贯穿本次补全的四大架构原则
🧹

先抽取再开发

发现 _RadarChart、_metricBar、_buildInsightCard 在 home_page 和 report_page 中完全重复（~300 行）。先将其抽取到 lib/widgets/ 公共组件库，后续所有新页面直接复用，从源头杜绝重复。

📋

Mock-First 策略

题库、社区、通知三个模块后端 API 尚未开发。每个模块封装独立的 Service 抽象层 （PostService、FavoriteService），当前返回本地 mock 数据，后端就绪后只需替换 Service 实现，UI 层零改动。

📦

渐进式 Provider 引入

不推倒重来。Login / Record / Report 等已稳定页面保持 setState 不变。 仅将跨页面共享状态（用户信息、报告列表、通知未读数）提升到 Provider， 新页面从一开始就用 context.watch<T>()。

🔌

WebSocket 替代轮询

WebSocketService（STOMP 协议）已完整实现但从未调用。 当前上传音频后靠 await + Future.delayed(2秒) 模拟分析进度。 接入 WebSocket 后可获得真实的 AI 分析进度推送，并支持降级回退。

设计 Token 一致性规范

所有新组件严格使用现有 Token，不引入新颜色/字号体系。
