🔍 一、当前项目处境

1.1 项目定位

InterviewMentorAI 是一款 AI 面试复盘工具：面试录音 → AI 自动转录 + 说话人分离 → RAG 增强评估 → 结构化复盘报告。当前处于原型验证阶段，具备完整的 AI 分析链路，但业务后端极其薄弱。

4.3 多租户 Schema 切换机制

核心思路：每个租户一个独立的 MySQL schema（如 tenant_001），公共平台数据在 platform schema。通过 Spring 拦截器在请求进入时根据 JWT 中的 tenantId 自动切换 USE schema。

请求进入 │ ▼ JWT Filter 解析 Token │ 提取 tenantId, userId, role ▼ TenantContext.set(tenantId) ← ThreadLocal 存储当前租户 │ ▼ MyBatis-Plus 拦截器 │ 执行: SET search_path TO tenant_{id} ▼ SQL 执行 (自动路由到对应 schema) │ ▼ 请求结束 → TenantContext.clear()

个人用户处理：个人用户注册后自动分配到 platform 公共租户，与 SaaS 租户走同一套 schema 机制。

@Configuration
@EnableAsync
public class AsyncConfig {
    
    @Bean("aiAnalysisExecutor")
    public Executor aiAnalysisExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(4);        // 核心线程: 4
        executor.setMaxPoolSize(8);         // 最大线程: 8
        executor.setQueueCapacity(50);      // 等待队列: 50
        executor.setThreadNamePrefix("ai-analysis-");
        executor.setRejectedExecutionHandler(new CallerRunsPolicy());
        executor.setKeepAliveSeconds(60);
        return executor;
    }
}

8.2 STOMP + SockJS 配置

@Configuration
@EnableWebSocketMessageBroker
public class WebSocketConfig implements WebSocketMessageBrokerConfigurer {
    
    @Override
    public void configureMessageBroker(MessageBrokerRegistry registry) {
        registry.enableSimpleBroker("/topic", "/queue");  // 消息代理前缀
        registry.setApplicationDestinationPrefixes("/app");  // 客户端发送前缀
    }
    
    @Override
    public void registerStompEndpoints(StompEndpointRegistry registry) {
        registry.addEndpoint("/ws")
                .setAllowedOriginPatterns("*")
                .withSockJS();  // 启用 SockJS 降级
    }
}

// Controller 推送消息
@Controller
public class InterviewWebSocketController {
    
    private final SimpMessagingTemplate messagingTemplate;
    
    public void sendStatusUpdate(Long interviewId, String status, int progress) {
        Map<String, Object> payload = new HashMap<>();
        payload.put("type", "status_update");
        payload.put("interviewId", interviewId);
        payload.put("status", status);
        payload.put("progress", progress);
        messagingTemplate.convertAndSend("/topic/interview/" + interviewId, payload);
    }
    
    public void sendReportReady(Long interviewId, String report) {
        Map<String, Object> payload = new HashMap<>();
        payload.put("type", "report_ready");
        payload.put("interviewId", interviewId);
        payload.put("report", report);
        messagingTemplate.convertAndSend("/topic/interview/" + interviewId, payload);
    }
}

🔗 九、双后端交互方案

9.1 Java → Python 调用链路

关键改变：从同步 restTemplate 改为异步 RestClient（Spring 6 内置）+ @Async。

维度当前方案MVP 方案
HTTP 客户端RestTemplate (同步阻塞)RestClient (Spring 6, 同步但非阻塞调用线程)
调用方式new Thread() + 同步等待@Async + 线程池, 不阻塞 Tomcat
结果通知同步返回后 WebSocket 手动推送@Async 完成后 STOMP 自动推送
超时处理无RestClient 超时 120s + 重试
错误处理简单 try-catch@Async 异常处理 + 标记 FAILED + STOMP 推送错误

9.2 Python AI 后端调整

Python 端不需要改动核心逻辑，只需在 API 层增加租户上下文传递：

# Python 侧请求格式保持不变
POST /api/v1/analysis/analyze
{
  "interview_id": 5001,
  "audio_file_path": "/data/audio/xxx.wav"
}

# 响应格式保持不变
{
  "status": "COMPLETED",
  "interview_id": 5001,
  "report": "# 面试复盘报告\n...",
  "evaluations": [...]
}

Python 端不感知租户概念，所有多租户逻辑由 Java 侧处理。音频文件路径由 Java 侧传入，Python 直接读取。
