1. 结果导向（Destination）

本次优化要到达的终点

终点是一个 Agent 自治的知识库管道：用户把任意格式的题库拖入指定目录， 后端 Agent 全程无需人工干预，自动完成 格式转换 → 数据清洗 → 结构化切面 → 向量化 → 幂等入库 → 自检验证， 并在此后的每次面试评估中提供 高质量检索（混合检索 + 重排）。

P1 · 入库自动化

拖入题库 → Agent 自动清洗/切面/入库，零手动脚本、零重复数据。

P2 · 检索质量

结构化切面 + 重排后置，弱项知识点的参考上下文命中率可量化提升。

P3 · 可观测自证

每一步有日志/统计/验收，Agent 以「自证入库成功」闭环，而非盲跑。

判定标准（Definition of Done）：拖入一份新题库 → 不手改任何代码 → Agent 日志输出清洗/切面/向量化/入库统计 → /api/v1/rag/knowledge/stats 文档数正确 → 检索接口对典型问题命中率达标。

D1 · 题目为一等概念

入库/清洗/切面/检索/评估均以「一道完整题目 Q-A」为基本单位；检索命中返回完整题目。

D2 · 单入口深度模块

入库收敛为 import_document(path)→ImportReport，HTTP 与 Agent 共用；否决 watchdog 常驻进程。

D3 · 幂等 + 生命周期

指纹比对跳过重复、变更替换、目录对账删旧；否决仅去重与全量重建。

D4 · 检索统一默认

接口与评估链路统一 use_hybrid=True + use_rerank=True；权重/阈值/top_k 入 config。

D5 · 自检闭环

入库后 stats 对账 + 抽样检索自测；不一致回滚并输出错误入库报告，失败不静默。

边界不变

不碰 Java t_knowledge_document、不换底层模型、不改前端、不引入多租户。

4. Agent 流程要求与边界

职责即边界，要求即验收
Agent 职责范围（In-Scope）
  • 1. 接收拖入的题库文件，自动判定格式并触发转换
  • 2. 执行数据清洗：去噪、规范化、去重（指纹）
  • 3. 结构化切面：识别题目/答案/评估要点，保留溯源元数据
  • 4. 向量化 + 幂等入库（增量/替换），全程日志可追踪
  • 5. 入库自检：stats 对账 + 抽样检索自测，产出入库报告
  • 6. 检索链路：混合检索 + 重排，评估阶段默认启用
  • 7. 以 MCP/工具接口暴露知识库管理（导入/更新/删除/统计）
边界（Out-of-Scope / 不做）
  • → 不触碰 Java 业务后端的 t_knowledge_document CRUD 与鉴权
  • → 不替换 LLM / ASR / Embedding 底层模型（仅参数化调优）
  • → 不改 Flutter 前端页面与交互
  • → 不引入多租户 / RBAC（纯个人模式，见 commit 151eeef）
  • → 不做跨文档语义级知识图谱（本期仅为题库 RAG 优化）
流程要求（Agent 硬约束）
幂等：重复导入不产生重复分块 可溯源：分块保留 source / 题号 / 标题 可回滚：文档级删除 / 替换 可观测：每步日志 + 统计 自证：入库后自动验证，失败不静默
