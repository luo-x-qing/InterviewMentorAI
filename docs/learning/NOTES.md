### 2026年8月6日 — RAG 检索质量修复 + Agentic 化

**背景：**
- `rag_query.py` 交互验证暴露检索质量问题：扫描版 3 号 PDF（485 页合集）82% 块是 `(cid:xxxx)` 乱码污染检索；超长题目被切成多块（如 1/6），检索只返回首块导致答案截断；部分命中与问题无关。

**学习/实践内容：**
1. **CID 乱码整页 OCR**：缺 ToUnicode 映射的 PDF，文字层提取出 `(cid:xxxx)` 垃圾。方案：`_is_cid_garbage` 以 `(cid:\d+)` 占比 >3% 判定乱码页 → 渲染 300dpi → RapidOCR 整页识别替代。3 号 PDF 题目数 36 → 885。
2. **入库块级过滤**：任何含 `(cid:` 的块一律不入库（兜底拦截漏网的半乱码块），并清理库内既有乱码块。
3. **题目识别规则**：句号结尾的题号行（≤15 字判列表项，中等长度判题目）避免子题并入上题；题号支持 `. 、 ． ) ]` 分隔。
4. **Agentic RAG（LangChain + LangGraph）**：
   - LangChain 提供标准化检索组件（`RagRetriever`：BaseRetriever/Document 封装混合检索+重排）
   - LangGraph 编排 检索→扩展→评估→（重查）→合成 工作流
   - `expand` 按（来源, 题号）拉取同一题全部块拼接 → 解决答案截断
   - `assess` 离线规则（相似度≥0.6 + 关键词重合）过滤无关候选，全不相关时二次检索
   - 两库下载在项目目录 `backend_python/lib/`（非全局环境），由模块顶部显式注入 `sys.path` 加载

**成果：**
- 检索「Spring Bean 生命周期」从命中混排块/无关候选 → 命中独立完整题目（题 786/885）
- 新增测试：agentic 工作流 12 项 + 文档转换 3 项，全量 **215 passed**
- 库备份：`interview.db.pre_period_rule` / `interview.db.pre_paren_rule`

**已知残留：**
- OCR 时题号与上文同段粘连（题号不在行首）的题目识别切不开（如「476) java 集合?」），需文本级粘连切割（有误切答案列表项风险）

**下一步计划：**
- 文本级粘连切割（需评估误切风险）
- 2 号 PDF 排版错位问题排查
